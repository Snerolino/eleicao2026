# 4. Metodologia usada neste dossiê

## 4.1 Separação obrigatória

Cada item tem, quando possível, três camadas:

1. **Fato legislativo**
   - proposição;
   - versão/objeto votado;
   - data;
   - voto bruto;
   - presença/ausência;
   - fonte oficial.

2. **Avaliação metodológica**
   - grupo afetado;
   - direção;
   - `defending_vote`;
   - severidade;
   - tipo estrutural;
   - racional;
   - confiança.

3. **Resultado derivado**
   - alinhamento;
   - peso;
   - contribuição ao score.

A camada 2 jamais modifica a camada 1.

## 4.3 Direção, tipo, severidade e confiança

`impact_direction`:

```text
positive | negative | mixed | unclear
```

`structural_type`:

```text
structural → fator 1,5
budgetary → fator 1,0
symbolic → fator 0,5
```

`severity`: 1–5.

`confidence`: 0–1.

Quando o impacto for `unclear`, `defending_vote` deve ser `null`.

---

## 4.4 Peso

```text
peso(assessment) = severity × fator(structural_type)
```

## 4.6 Regra anti-duplicação

Uma mesma proposição pode ter:

- requerimento de urgência;
- retirada de pauta;
- emendas;
- destaques;
- primeiro turno;
- segundo turno;
- emenda de redação.

Todos podem ser preservados como fatos.

Mas o score não deve contar cada etapa como se fosse uma política pública independente.

### Regra provisória v0.1.0

Quando houver múltiplos registros de uma mesma proposição/versão, usar apenas a **última votação substantiva aplicável ao objeto analisado** como unidade de score, sem apagar as demais ocorrências.

---

## 4.7 Ausência e licença

Somente classificar `absence_type = estrategica` quando houver evidência direta específica.

Exemplos:

```text
licença ministerial → sem_dado
missão autorizada → justificada
licença médica → justificada
obrigação político-partidária documentada → justificada, salvo metodologia futura
ausência sem contexto → não presumir estratégia
```

---

## 4.8 Taxonomia insuficiente não significa neutralidade

Se uma proposição atinge trabalhadores formais, servidores públicos ou trabalhadores submetidos a condição análoga à escravidão e a taxonomia não contém esse grupo, registrar:

```yaml
taxonomy_gap: true
score_included: false
```

Não deslocar o tema para o slug “mais parecido”.

---

## 4.9 Governança

Avaliações com:

```text
severity >= 4
```

ou:

```text
confidence < 0.6
```

permanecem `pending_review` até a revisão humana prevista pela metodologia.

# 15. Regras de uso deste arquivo

Este dossiê pode ser utilizado como:

- referência documental;
- seed para ingestão;
- conjunto de teste da Matriz de Impacto;
- base para revisão humana;
- mapa de lacunas para pesquisa incremental.

## 15.1 Campos factuais

Devem continuar ligados à fonte:

```text
candidate_name
mandate
office
party
proposition_id
date
voting_object
raw_vote
attendance
absence_justification
authorship
rapporteurship
legislative_status
source
```

## 15.2 Campos derivados/revisáveis

Nunca devem ser promovidos a “fato oficial”:

```text
beneficiary_group
severity
structural_type
impact_direction
defending_vote
confidence
alignment
score
taxonomy_gap
```

## 15.3 Princípio de auditoria

Qualquer conclusão deve permitir navegar no sentido inverso:

```text
score
  ↓
alignment
  ↓
assessment
  ↓
voto/ação factual
  ↓
proposição/versão
  ↓
fonte oficial
```

Se essa reconstrução não for possível, o item não está pronto para publicação.
